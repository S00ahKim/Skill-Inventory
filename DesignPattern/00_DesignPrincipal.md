# 디자인 원칙

- [캡슐화] 애플리케이션에서 달라지는 부분들을 찾아내서 달라지지 않는 부분으로부터 분리한다
    * 일단 구현하고 분리하는 방법, 미리 예상해서 분리하는 방법 등
    * examples
        + [스트래티지 패턴](01_StrategyPattern.md) 핵심 로직과 변하는 부분을 분리함
        + [옵저버 패턴](./02_ObserverPattern.md) 서브젝트의 상태에 의존하는 객체들을 바꿀 수 있음
- 구현이 아닌 인터페이스에 맞춰서 프로그래밍 한다
    * = 상위 형식에 맞춰서 프로그래밍한다
    * 자바의 인터페이스를 사용하라는 의미가 아니라 객체가 코드가 아니라 상위 형식(supertype)에 의해 맞춰지도록 다형성을 활용하라는 것
    * examples
        + [스트래티지 패턴](01_StrategyPattern.md)
        + [옵저버 패턴](./02_ObserverPattern.md) 자바의 옵저버 인터페이스 사용
- 상속 보다는 구성(composition)을 활용한다
    * A는 B이다 (상속) / A에는 B가 있다 (구성)
    * 올바른 행동 객체로 구성하면 행동을 부여받는 방식
    * 상속보다 구성이 더 유연하다
    * 실행시에 행동을 동적으로 바꿀 수 있다
    * examples
        + [스트래티지 패턴](01_StrategyPattern.md)
        + [옵저버 패턴](./02_ObserverPattern.md) 서브젝트와 옵저버 사이의 관계는 구성
- 서로 상호작용을 하는 객체 사이에서는 가능하면 느슨하게 결합하는 디자인을 사용해야 한다
    * examples
        + [옵저버 패턴](./02_ObserverPattern.md) 서브젝트와 옵저버는 느슨하게 결합됨
- [OCP] 클래스는 확장에 대해서는 열려 있고 변경에 대해서는 닫혀 있어야 한다 
- [DIP] 추상화된 것에 의존하게 하고 구상 클래스에 의존하도록 하지 말라
    * 고수준 구성요소가 저수준 구성요소에 의존하면 안 된다
    * 고수준 구성요소와 저수준 구성요소가 모두 추상 클래스에 의존하게 하라 (일반적인 방법과 반대로 뒤집어 생각해야)
