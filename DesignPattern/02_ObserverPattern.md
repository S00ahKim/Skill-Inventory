# 옵저버 패턴

- 한 객체의 상태가 바뀌면 그 객체에 의존하는 다른 객체들한테 연락이 가고 자동으로 내용이 갱신되는 방식으로 일대다 의존성을 정의함
    * subject의 상태가 바뀌면 observer에게 연락이 감
    * 연락 방법에 따라 옵저버에 있는 값이 새로운 값으로 갱신될 수도 있음
- 느슨한 결합 loose coupling
    * 서브젝트가 옵저버에 대해 아는 것은 옵저버가 특정 인터페이스를 구현한다는 것뿐임
    * 옵저버는 언제든 새로 추가할 수 있음
    * 새로운 옵저버를 추가할 때 서브젝트를 변경할 필요 없음
    * 서브젝트와 옵저버는 서로 독립적으로 재사용 가능
    * 서브젝트나 옵저버가 바뀌어도 서로에게 영향을 미치지 않음
- 데이터를 보내는 방식
    * 푸시 방식: 서브젝트가 데이터를 보냄
    * **풀 방식: 옵저버가 데이터를 가져가는 방식**
    * 옵저버에게 연락을 돌리는 순서에 절대 의존하면 안 된다
- 자바 내장 옵저버 패턴
    * java.util.Observer 인터페이스 (옵저버)
    * java.util.Observable 클래스 (서브젝트)
        + 서브클래스를 만들어야만 하고, 직접 구현을 할 수 없다
        + 핵심 메서드를 외부에서 호출할 수 없다
- JDK에서 옵저버 패턴을 쓴다: JavaBeans, Swing, GUI 프레임워크
