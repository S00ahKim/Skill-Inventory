# 싱글턴 패턴

- 객체 인스턴스를 하나만 만들고, 어디서든지 거기에 접근 가능하게 하는 패턴
- 하나만 있어도 되는 객체 예시
    * 스레드 풀
    * 캐시
    * 대화상자
    * 사용자 설정 / 레지스트리 설정 처리 객체
    * 로그 기록용 객체
    * 프린터나 그래픽 카드 등 디바이스를 위한 디바이스 드라이버
- 하나만 있어야 하는데 여러 객체가 생긴다면 생길 수 있는 문제점
    * 프로그램이 이상하게 동작
    * 자원을 불필요하게 잡아먹음
    * 결과에 일관성이 없어짐
- 싱글턴 패턴의 기타 장점
    * 전역 변수를 사용할 때처럼 객체 인스턴스를 어디서든 액세스하게 할 수 있음
    * 전역 변수의 단점 보완 (필요할 때만 객체 생성 가능, 클래스 인스턴스 하나만 보유 가능)
        + 전역 변수를 사용하면 전역 레퍼런스 수가 늘어나 네임스페이스가 지저분해질 수 있음
- 방법
    * private 생성자와 getInstance() 정적 메소드, 정적 변수 조합
- 멀티스레딩 문제
    * 성능이 중요하지 않다면 getInstance를 동기화한다
    * 무조건 사용될 인스턴스라면 인스턴스를 필요할 때 생성하지 말고 처음부터 만들어둔다
    * DoubleCheckingLocking을 써서 동기화되는 부분을 줄여준다 (volatile 멤버변수, getInstance 내부의 부분적 동기화)
- 가비지 콜렉터 문제
    * JVM 1.2 이전에는 버그가 있었으나 이후 해소됨
- 클래스 로더 문제
    * 여러 클래스 로더를 사용하면 싱글턴도 여러 개 만들어질 수 있음
    * 직접 클래스 로더를 지정하여 해결 가능
